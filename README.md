# Вместе — Backend

Реальный бэкенд для прототипа «Вместе» (digital parenting): Node.js + Express 5 + Postgres,
с авторизацией, ролями «родитель/ребёнок» и полноценной базой данных вместо стейта в браузере.

**Что это меняет по сравнению с прототипом на React:** там всё жило в памяти вкладки и
обнулялось при перезагрузке. Здесь данные лежат в настоящей базе, у родителя и ребёнка —
отдельные аккаунты с паролями, и один человек не может внезапно увидеть или изменить данные
чужой семьи (это проверяется на каждом запросе).

**Чего это НЕ делает** (и не может сделать ни один веб-бэкенд): не считает реальное экранное
время, не блокирует приложения и не определяет геопозицию на телефоне ребёнка. Это требует
нативных iOS/Android-приложений с системными разрешениями — отдельный проект. Здесь для этого
есть честная заглушка: `POST /api/usage/log` — эндпоинт, который в реальном продукте вызывал бы
агент на устройстве ребёнка; сейчас его можно дёргать вручную, чтобы увидеть, как обновляется
статистика.

## Стек

- **Node.js 18+** и **Express 5**
- **Postgres** через драйвер `pg` (node-postgres). Раньше здесь был встроенный `node:sqlite`
  (файл на диске) — перешли на Postgres, потому что бесплатные тарифы большинства хостингов
  (Render и т.п.) дают только эфемерную файловую систему: локальный файл SQLite стирается при
  каждом рестарте/деплое/уходе в сон. Postgres же можно взять бесплатно и постоянно у Supabase
  (или похожих провайдеров) — данные живут отдельно от сервера и не зависят от его перезапусков.
- **JWT** (`jsonwebtoken`) для авторизации, **bcryptjs** для паролей (без нативных зависимостей)

## Быстрый старт

Понадобится **Node.js 18 или новее** (`node --version`) и строка подключения к Postgres —
в отличие от старой SQLite-версии, без базы сервер теперь не стартует вообще.

Самый быстрый способ получить бесплатный Postgres без установки чего-либо локально —
завести проект на [supabase.com](https://supabase.com) (бесплатно, без карты) и взять из
него Connection string (Project Settings → Database → Connection string → Transaction
pooler). Подробности и альтернативы — в DEPLOY.md.

```bash
cp .env.example .env
# впишите в .env свой DATABASE_URL (из Supabase или локального Postgres)

npm install
npm run dev
```

При первом запуске сервер сам создаст таблицы и заполнит их демо-данными (та же Соня
и те же квесты/уведомления, что в прототипе). В консоли появятся логин и пароль:

```
Родитель: parent@demo.family / demo1234
Ребёнок:  sonya@demo.family / demo1234
```

Проверить, что всё работает: `curl http://localhost:4000/api/health`

Есть и скрипт-самопроверка, который прогоняет весь сценарий (логин → одобрение запроса →
квест → история и т.д.) и печатает ответы каждого шага — удобно после любых правок:

```bash
./test.sh
```

(он полностью очищает базу перед прогоном — `npm run reset` под капотом — так что не
запускайте его на данных, которые жалко потерять; для теста лучше отдельный Postgres,
а не тот, где уже живут настоящие данные семьи)

## Структура проекта

```
src/
  server.js          — точка входа
  app.js             — сборка Express-приложения и роутов
  db/
    schema.sql        — все таблицы (Postgres-диалект)
    connection.js      — pg-пул + хелперы queryOne/queryAll/execute + транзакции
    migrate.js         — создаёт таблицы
    seed.js            — демо-данные (семья Сони)
    reset.js           — только для разработки/тестов: очищает всё, сбрасывает ID (npm run reset)
  middleware/
    auth.js             — проверка JWT и ролей
    errorHandler.js
  routes/              — по одному файлу на группу эндпоинтов (ниже)
  utils/
```

## API

Все маршруты, кроме `/api/health`, `/api/auth/register` и `/api/auth/login`, требуют заголовок
`Authorization: Bearer <token>`. Роль проверяется на сервере — «ребёнок» не может дёрнуть
родительский эндпоинт, даже если знает URL.

| Метод | Путь                        | Роль        | Что делает |
|-------|-----------------------------|-------------|------------|
| POST  | `/api/auth/register`        | —           | Создать семью + родительский аккаунт |
| POST  | `/api/auth/register-child`  | parent      | Добавить ребёнка в свою семью |
| POST  | `/api/auth/login`           | —           | Войти, получить токен |
| GET   | `/api/auth/me`               | любая       | Текущий пользователь |
| GET   | `/api/overview`              | любая       | Кольцо времени, топ-3 приложения, статус, категории |
| GET   | `/api/settings`              | любая       | Лимит + расписание блокировок |
| PUT   | `/api/settings/limit`        | parent      | Изменить дневной лимит |
| PUT   | `/api/settings/schedule/:id` | parent      | Включить/выключить блок расписания |
| GET   | `/api/alerts`                | parent      | Лента ИИ-уведомлений |
| POST  | `/api/alerts/:id/discuss`    | parent      | Отметить «обсудили с ребёнком» |
| GET   | `/api/quests`                | любая       | Список квестов |
| POST  | `/api/quests/:id/submit`     | child       | Отправить квест на проверку |
| GET   | `/api/requests?status=`      | любая       | Список запросов (фильтр по статусу опционален) |
| POST  | `/api/requests`              | child       | Попросить доп. время / разблокировку |
| POST  | `/api/requests/:id/respond`  | parent      | Одобрить/отклонить, с комментарием |
| GET   | `/api/history`               | любая       | Последние решения родителя |
| POST  | `/api/usage/log`             | child       | Заглушка «устройство сообщило об использовании» |
| GET   | `/api/location`              | любая       | Заглушка геопозиции |

### Пример: полный цикл квеста

```bash
# войти ребёнком
curl -X POST localhost:4000/api/auth/login -H "Content-Type: application/json" \
  -d '{"email":"sonya@demo.family","password":"demo1234"}'
# → сохраните token из ответа как CHILD_TOKEN

curl -X POST localhost:4000/api/quests/1/submit -H "Authorization: Bearer $CHILD_TOKEN"

# войти родителем, одобрить — запрос появится в GET /api/requests?status=pending
curl -X POST localhost:4000/api/requests/4/respond -H "Authorization: Bearer $PARENT_TOKEN" \
  -H "Content-Type: application/json" -d '{"decision":"approved","comment":"Отлично!"}'
```

## Подключение фронтенда

React-прототип, который мы делали раньше, хранит всё в `useState` внутри одной вкладки —
он не умеет обращаться к этому API «из коробки». Чтобы соединить их, в `App()` нужно заменить
локальный стейт на запросы к этим эндпоинтам (и добавить экран входа). Пример для одного куска
— замена статичного списка запросов на реальные данные:

```js
// было:
const [requests, setRequests] = useState(INITIAL_REQUESTS);

// станет:
const [requests, setRequests] = useState([]);
useEffect(() => {
  fetch(`${API_URL}/requests`, { headers: { Authorization: `Bearer ${token}` } })
    .then((r) => r.json())
    .then((d) => setRequests(d.requests));
}, [token]);
```

Остальные разделы (квесты, лимиты, история и т.д.) переносятся тем же способом: каждый
`useState` с мок-данными меняется на `fetch` к соответствующему эндпоинту из таблицы выше.
Если понадобится — могу переписать весь фронтенд под это API отдельным заходом, это отдельный
по объёму кусок работы.

Учтите: превью артефакта в самом чате Claude.ai выполняется в песочнице и, скорее всего, не
сможет достучаться до `localhost` на вашей машине. Для реальной интеграции фронтенд тоже
нужно будет запускать локально (или задеплоить оба вместе) — просто открыть артефакт в чате
не получится.

## Переменные окружения

Скопируйте `.env.example` в `.env`. Сервер прекрасно работает и без него (со значениями по
умолчанию), но **обязательно** задайте свой `JWT_SECRET` перед любым деплоем за пределы
вашего компьютера — иначе кто угодно сможет подделать токен.

## Деплой

Это обычное Express-приложение, значит подойдёт любой хостинг с поддержкой Node.js —
например Render, Northflank, VPS. Важное отличие от старой SQLite-версии: теперь данные
живут в Postgres отдельно от самого сервера, поэтому эфемерная файловая система хостинга
(частая история у бесплатных тарифов) больше не проблема — база не привязана к диску
контейнера и переживает рестарты/редеплои сама по себе. Три момента, о которых стоит помнить:

1. Заведите Postgres (например, бесплатный проект на Supabase — без карты, без срока
   действия, просто засыпает при 7 днях полного бездействия и просыпается по первому
   запросу) и задайте `DATABASE_URL` через переменные окружения хостинга.
2. Задайте свой `JWT_SECRET` там же — не коммитьте `.env` в git.
3. Сузьте `cors()` в `src/app.js` (переменная `CORS_ORIGIN`) до конкретного домена
   фронтенда вместо открытого доступа для всех.

Полная пошаговая инструкция (Render + Supabase, плюс VPS про запас) — в DEPLOY.md.

## Известные упрощения этого стартера

- У «ребёнка» пока обычные email+пароль — в реальном продукте для детей обычно делают
  вход попроще (PIN, привязка к аккаунту родителя без отдельного email).
- Одна семья = один ребёнок в демо-данных, но схема БД уже поддерживает нескольких детей
  (просто вызовите `/api/auth/register-child` ещё раз).
- `streak_count` («дней подряд») — простое число в базе, не вычисляется автоматически из
  истории квестов. Для реального продукта это стоит сделать отдельным job'ом.
- Нет rate limiting и нет отправки email (подтверждение регистрации, сброс пароля) —
  для продакшена обычно добавляют `express-rate-limit` и почтовый сервис.
